# 13 — Customer Dashboard ("My Garage")

> **Status:** Planning
> **Priority:** High
> **Dependencies:** `11-provider-dashboard.md` (shared shell patterns), `04-vehicles` integration plan, existing appointments/payments domain
> **Audit findings resolved:** N/A
> **Design source:** `raycarwash/project/Customer Dashboard.html` + `raycarwash/project/src/cdash.css`
> **Note:** Unlike the Provider Dashboard, no JSX components were generated by Claude Design. The HTML manifest lists `cdash-home`, `cdash-bookings`, `cdash-track`, `cdash-garage`, `cdash-rewards`, `cdash-account` as the views (the files do not exist in the bundle). The CSS gives us **all the visual primitives** — this plan infers the data and component structure from those primitives.

---

## 1. Objective

Ship a customer dashboard at `web/portal/app/[locale]/(app)/client/dashboard/*` (Next.js, port 3001). The customer site is mobile-first but most users will book from the React Native app — the dashboard is for **viewing/managing bookings from desktop**, plus power-user features like multi-vehicle, recurring subscriptions, rewards, and address book.

The page is titled "My Garage" in the design.

## 6. API endpoints

### 6.1 Home
- `GET /api/v1/me/dashboard/home` — composite. Returns: next booking (with detailer mini), top 3 recommended services, last 2 receipts, loyalty summary, recent activity.

### 6.2 Bookings
- `GET /api/v1/me/appointments?status=&cursor=` (reuses existing `/appointments/mine?as=client`).
- `GET /api/v1/me/appointments/{id}` — full detail.
- `POST /api/v1/me/appointments/{id}/reschedule` (FSM-aware).
- `POST /api/v1/me/appointments/{id}/cancel`.
- `GET /api/v1/me/appointments/{id}/receipt.pdf` — signed S3 URL.
- `GET /api/v1/me/appointments/{id}/timeline` — step-by-step events.
- `GET /api/v1/me/appointments/{id}/photos` — before/after gallery.

### 6.3 Track
- `WS /ws/appointments/{id}?token=` (exists) — pushes detailer location.
- `GET /api/v1/me/appointments/{id}/track` — initial state (last known loc, ETA, status).
- `GET /api/v1/me/appointments/{id}/eta` — current ETA in minutes.

### 6.4 Garage
- `GET/POST/PATCH/DELETE /api/v1/me/vehicles` (exists; extend with photo upload).
- `POST /api/v1/me/vehicles/{id}/photos` — multipart.
- `GET /api/v1/me/vehicles/{id}/stats` — visits + total_spent + last_service.
- `GET /api/v1/me/vehicles/{id}/history` — all appointments for this vehicle.
- `GET /api/v1/me/subscriptions` · `POST/PATCH/DELETE` for subscriptions.

### 6.5 Rewards
- `GET /api/v1/me/loyalty` — account summary (points, tier, perks).
- `GET /api/v1/me/loyalty/ledger?cursor=` — points history.
- `GET /api/v1/loyalty/tiers` — static tier definitions (public).
- `POST /api/v1/me/loyalty/redeem` — redeem perk → returns discount code or applies credit.
- `GET /api/v1/me/referrals` — list (code, status, rewards earned).
- `POST /api/v1/me/referrals/share` — get share link/code.
- `POST /api/v1/referrals/{code}/claim` — claimed by referee on signup.

### 6.6 Account
- `GET/PATCH /api/v1/me/profile`.
- `GET/POST/PATCH/DELETE /api/v1/me/addresses` (exists).
- `GET/POST/DELETE /api/v1/me/payment-methods` (exists; needs default-setting endpoint).
- `PATCH /api/v1/me/payment-methods/{id}/default`.
- `GET /api/v1/me/favorites/providers` · `POST/DELETE` for favorites.
- `GET/PATCH /api/v1/me/notification-prefs` (shared schema with provider).
- `POST /api/v1/me/exports`.
- `POST /api/v1/me/pause` · `DELETE /api/v1/me` (soft-delete).

### 6.7 Recommendations
- `GET /api/v1/me/recommendations?limit=` — Phase 1 rule-based, Phase 2 ML.
- `POST /api/v1/me/recommendations/{id}/dismiss`.

## 7. Loyalty system design

### 7.1 Points earning rules (defaults; admin-tunable via plan 15)
| Event | Points |
|---|---|
| Booking completed | 1 point per $1 spent |
| Tip added | 0.5 points per $1 |
| Review left (5★) | +20 bonus |
| Referral redeemed by friend | +500 |
| Birthday | +250 (annual) |
| Recurring booking maintained 4 cycles | +200 |

### 7.2 Tier thresholds
- **Bronze**: 0 pts (default)
- **Silver**: 500 lifetime pts
- **Gold**: 2,000 lifetime pts
- **Platinum**: 5,000 lifetime pts

### 7.3 Tier perks (admin-tunable)
- **Silver**: 10% off detail, priority booking
- **Gold**: 15% off, free Express monthly, dedicated support
- **Platinum**: 20% off, free Full detail quarterly, line-skip

### 7.4 Redemption
1 point = $0.01 redeemable credit. Min redemption 500 pts ($5). Applied at checkout as a `LedgerEntry` of kind `credit_redeem`.

## 8. Execution phases

### Phase 1 — Read-only Core (Weeks 1–2)
- `GET /me/dashboard/home`
- Vehicle stats endpoint
- Bookings list + detail (reuses existing)
- Track endpoint (initial state + WS) — desktop view of existing flow

### Phase 2 — Garage + Subscriptions (Weeks 3–4)
- `Subscription`, `SubscriptionRun` models
- Vehicle photo upload

### Phase 3 — Rewards (Weeks 5–6)
- `LoyaltyAccount`, `LoyaltyLedger`, `LoyaltyTier`, `Referral`

- Redemption flow

Frontend: Rewards view (points, tiers, perks, history, referrals).

### Phase 4 — Account & Personalization (Weeks 7–8)
- Favorites endpoint
- Receipt PDF generator (background worker, S3 storage)
- Address default + notes (geofence radius)
- Payment method default toggle

Frontend: Account view (profile, addresses, payments, favorites, prefs).

### Phase 5 — Recommendations (Weeks 9+)
- Phase 1 rule-based recommendation engine
- Phase 2 (future) ML model with collaborative filtering

Frontend: Recommendations on Home view.

## 11. Risks

| Risk | Mitigation |
|---|---|
| No JSX prototypes — design language must be inferred from CSS classes | Build one view first (Home), get user sign-off on visual fidelity before scaling |
| Subscription cron complexity (timezones, holidays) | Use existing `workers/` async pattern; UTC-only with explicit timezone conversion on display |
| Loyalty points can be gamed (refund-loop) | All earning hooks fire on `completed` state only; deduct on full refund |
| Recommendation engine cold-start (no history) | Phase 1 falls back to "popular services in your area" heuristic |
| Mobile app vs web dashboard data divergence | Both consume same `/api/v1/me/*` endpoints; mobile shows subset |
| Address geofence radius edge cases | Default 50m, admin-tunable in plan 15 |
| Receipt PDFs accumulate S3 storage cost | Lifecycle policy: move to Glacier after 1 year |
